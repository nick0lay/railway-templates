# StarRocks Railway Template Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `solutions/starrocks/` Railway template that deploys single-node StarRocks (FE + BE) from the official all-in-one image, with a persistent volume, a public FE web UI / Stream Load endpoint, and a Railway-generated root password.

**Architecture:** One Railway service built from `starrocks/allin1-ubuntu`, which runs FE, BE, an nginx front proxy, and a bootstrap `director` under supervisord — all communicating over `127.0.0.1`, which is what makes it work on Railway's IPv6-only private network. A thin wrapper entrypoint adapts the image to Railway: it symlinks the two stateful directories into the single mounted volume, rebinds the nginx proxy to `$PORT`, caps BE memory, and applies `STARROCKS_PASSWORD` to the `root` account on first boot.

**Tech Stack:** Docker, Bash, StarRocks 4.x (`starrocks/allin1-ubuntu`), Railway (volumes, TCP Proxy, `${{secret(32)}}` template variables).

## Global Constraints

- Spec: `docs/superpowers/specs/2026-08-02-starrocks-railway-template-design.md`. Every requirement there applies.
- Base image: `starrocks/allin1-ubuntu`, default tag `latest`, overridable through the `STARROCKS_IMAGE_TAG` build arg — same pattern as `solutions/clickhouse-chui/clickhouse/Dockerfile` and `solutions/questdb/questdb/Dockerfile`.
- Do **not** override the image's `ENTRYPOINT`; it is `tini-static` and must stay PID 1. Override `CMD` only.
- Inside the image: `SR_HOME=/data/deploy/starrocks`, `WORKDIR=/data/deploy`, upstream script is `./entrypoint.sh`.
- Volume mount path: `/var/lib/starrocks`. Never mount over `/data/deploy/starrocks` — Railway volumes mount empty and would hide the installed binaries.
- The password is generated by Railway (`${{secret(32)}}`), never by the container. The container only applies it.
- Docs follow `CLAUDE.md` conventions: ASCII architecture diagram, services table, env vars split into "User-Configurable" and "Auto-Configured (Do Not Change)", troubleshooting section, and the root `README.md` must be updated with both a Solutions-table row and a Structure-tree entry.

- [ ] **Step 1: Write the Dockerfile**

`solutions/starrocks/starrocks/Dockerfile`:

```dockerfile
# Use the official StarRocks all-in-one image (FE + BE in one container)
# Can be overridden by Railway environment variable `STARROCKS_IMAGE_TAG`
ARG STARROCKS_IMAGE_TAG
FROM starrocks/allin1-ubuntu:${STARROCKS_IMAGE_TAG:-latest}

# Wrapper that adapts the image to Railway (volume, dynamic PORT, root password)
COPY railway-entrypoint.sh /railway-entrypoint.sh
RUN chmod +x /railway-entrypoint.sh

# HTTP surface only: the FE web UI, REST API and Stream Load are proxied by the
# bundled nginx. The MySQL port (9030) is reached through Railway's TCP Proxy,
# which is configured with an explicit port and does not rely on EXPOSE.
EXPOSE 8080

# ENTRYPOINT is inherited on purpose: the image sets it to tini-static, which
# must remain PID 1 to reap the background password job.
CMD ["/railway-entrypoint.sh"]
```

- [ ] **Step 2: Write the wrapper entrypoint**

`solutions/starrocks/starrocks/railway-entrypoint.sh`:

```bash
#!/bin/bash
# Railway wrapper around the StarRocks allin1 entrypoint.
#
# Adapts the official image to Railway: a single mounted volume, a dynamic
# $PORT for the public HTTP surface, and a root password taken from the
# Railway-generated STARROCKS_PASSWORD variable.
set -e

SR_HOME="${SR_HOME:-/data/deploy/starrocks}"
DATA_DIR="${STARROCKS_DATA_DIR:-/var/lib/starrocks}"
PASSWORD_MARKER="$DATA_DIR/.root_password_set"
FE_QUERY_PORT=9030

log() { echo "$(date --rfc-3339=seconds) [railway] $*" >&2; }

# 1. Point FE metadata and BE storage at the Railway volume.
#    Railway mounts a single, empty volume, so the image's install directory
#    cannot itself be the mount point — symlink the two stateful directories
#    into the volume instead. Upstream's entrypoint.sh and director/run.sh read
#    $SR_HOME/fe/meta/{image/VERSION,image/ROLE} by literal path, so the paths
#    must keep working; repointing meta_dir/storage_root_path would not.
mkdir -p "$DATA_DIR/fe-meta" "$DATA_DIR/be-storage"
rm -rf "$SR_HOME/fe/meta" "$SR_HOME/be/storage"
ln -sfT "$DATA_DIR/fe-meta" "$SR_HOME/fe/meta"
ln -sfT "$DATA_DIR/be-storage" "$SR_HOME/be/storage"
log "FE meta -> $DATA_DIR/fe-meta, BE storage -> $DATA_DIR/be-storage"

# 2. Bind the bundled nginx proxy to Railway's dynamic port. The image
#    regenerates feproxy.conf from this template on every boot, so patching the
#    template is what sticks. The substitution matches any port number, which
#    keeps it safe to re-run against an already-patched file.
sed -i -E "s/^([[:space:]]*)listen[[:space:]]+[0-9]+;/\1listen ${PORT:-8080};/" \
    "$SR_HOME/feproxy/feproxy.conf.template"
log "feproxy will listen on ${PORT:-8080}"

# 3. Cap BE memory. Left alone, the BE sizes itself from memory it may not
#    actually be allowed to use, and gets OOM-killed into a restart loop.
if ! grep -Eq '^[[:space:]]*mem_limit[[:space:]]*=' "$SR_HOME/be/conf/be.conf"; then
    echo "mem_limit = ${STARROCKS_BE_MEM_LIMIT:-80%}" >> "$SR_HOME/be/conf/be.conf"
    log "BE mem_limit set to ${STARROCKS_BE_MEM_LIMIT:-80%}"
fi

# 4. Root password. StarRocks always boots with a passwordless root account, so
#    the Railway-generated password has to be applied over SQL once.
if [ -n "$STARROCKS_PASSWORD" ]; then
    if [ -f "$PASSWORD_MARKER" ]; then
        # Already applied on an earlier boot. The image's own bootstrap client
        # reads MYSQL_PWD, so it needs the password to authenticate.
        export MYSQL_PWD="$STARROCKS_PASSWORD"
        log "root password already applied; MYSQL_PWD exported for the bootstrap client"
    else
        # First boot: MYSQL_PWD must stay unset, because sending a password to
        # an account that has none fails with error 1045 and the image's
        # director treats that as fatal. Wait for bootstrap_done — director
        # touches it after its last SQL statement — then set the password.
        (
            set +e
            while [ ! -f "$SR_HOME/bootstrap_done" ]; do sleep 2; done
            escaped=${STARROCKS_PASSWORD//\\/\\\\}
            escaped=${escaped//\'/\\\'}
            for _ in $(seq 1 30); do
                if mysql -h 127.0.0.1 -P "$FE_QUERY_PORT" -u root --batch \
                        -e "SET PASSWORD FOR 'root'@'%' = PASSWORD('$escaped');"; then
                    touch "$PASSWORD_MARKER"
                    log "root password applied"
                    exit 0
                fi
                sleep 2
            done
            log "ERROR: could not set the root password; root is still passwordless"
        ) &
    fi
else
    log "STARROCKS_PASSWORD is empty; leaving the root account passwordless"
fi

# 5. Hand over to the image's own entrypoint (WORKDIR is /data/deploy).
exec ./entrypoint.sh
```
